# 記憶の欠片

これはプレイヤーが有効化を選ぶ、物語上の成長線である。Host は、人物の曖昧な個人的過去を意識的に探る場面、または強い連想が生じる場面で、曖昧で未確認の感覚的な断片を現在の module に追加できる。プレイヤーは右側の拡張 slot で、進行、stage、四つの dimension、完全な一覧を確認できる。

この説明は、プレイヤーが今回の冒険で「記憶の欠片」を有効にした場合にだけ適用する。説明を読めること自体は有効化を意味しない。長期記憶の検索、確認済みの世界の事実、基本的な人物設定、物語の結末と混同しない。

## 欠片が生じる条件

- プレイヤーが人物の曖昧な過去や生い立ちを明確に探ろうとした場合、「active recall」の欠片を一つ作れる。
- 今回の冒険で既に見聞きしたことや会話を思い返す場合は、これまでの出来事の検索として扱い、新たな過去の欠片を自動生成しない。
- 現在の人物、物品、匂い、音、動作、場所が人物の過去と強く結び付いた場合、「passive association」の欠片を一つ作れる。
- 一 game day につき active recall 一つ、passive association 一つまで。自然な trigger がなければ、進行を増やすために生成しない。
- 一日の上限は新しい発見だけに適用する。既存の欠片を読み返しても発見枠は消費せず、新しい欠片も自動的には追加しない。出典にない細部は不明のままにする。
- 人物作成中と開始を確認するターンには欠片を生成しない。開始の確認が済んだ後の自由な冒険でのみ発見できる。
- 同じ trigger を繰り返さず、新しい内容は既存の欠片と高い類似性を持たせない。
- 各欠片は body、emotion、skill、identity の四 dimension のうち一つだけに属する。

普通の休息、inventory の反復確認、「昔」と軽く触れただけ、数を埋めるだけの行動は十分な条件ではない。Skill trigger はこの説明の発見を助けるだけで、自動 generator ではない。

## 欠片の書き方

- 2-4 文の具体的だが不完全な感覚内容にする。身体に残った動き、感情反応、音、匂い、触感、短い映像を含めてよい。
- `uncertain` を保つ。欠片は過去の一つの可能性であり、NPC、World、Semantic Memory の確認済み事実ではない。
- 完全な身元を直接明かさず、本名、勢力、罪、親族関係、唯一の identity を代わりに確定しない。
- モデルの推論、prompt、file path、tool process、source analysis を欠片に書かない。

## 本文と記録の一致

この説明は物語上の判断基準を示す。利用できる操作、項目、復旧方法は現在のエンジンの規約に従い、独自の書き込みツールや再試行手順は設けない。

- 新しい欠片の内容は、省略せず同じ言葉で、このターンのプレイヤーに見える本文にも含める。きっかけだけを描き、欠片そのものを記録の中に隠してはならない。
- 欠片の記録、再構成に関するプレイヤーの選択、対応する本文は、ターン全体として検証し、一緒に確定する。本文より先に個別に書き込まない。番号、日付、出典、進行はエンジンが管理する。
- ターン全体が正常に確定するまでは、新しい欠片や選択が成立したことにせず、進行も増やさない。キャンセル、失敗、再試行はエンジンに任せる。
- 修正で新しい欠片や選択を撤回する場合、対応する新しい欠片の本文や、選択が成立したとする描写も削除または書き直す。他の有効な本文は残せるが、ターン全体の確定は必要である。
- 欠片は合計 30 個まで。日付の変更、同じきっかけの反復、別の書き込み経路で上限を回避しない。

## 記憶の再構成

30 個目は、自然な「記憶を再構成する」場面を解放するだけで、そのターンには再構成の選択を行わない。解放が確定した後のターンに、通常の物語を通じて自由に選んでもらう。上限に達しても冒険を自動終了せず、過去が真実だと証明もしない。明確な意思がなければ代わりに選ばない。

- 過去を受け入れる：`choice=accepted`。「記憶を取り戻した者」の称号は、この自己物語を能動的に受け入れたことを示す。system が絶対的な歴史だと証明した意味ではない。
- 過去を受け入れない：`choice=sealed`。すべての欠片を経験として残しつつ、過去を手放し、新しい自分を選び形作れることを明確にする。失敗 route ではなく、罰も与えない。
- 決定を保留する：`choice=deferred`。後に再びこの過去と向き合う明確な機会があれば、受け入れるか否かを選べる。

今回の入力でプレイヤーが明確に選んだ場合だけ、現在のエンジンの規約に従って、その選択を対応する本文と一緒に提出する。過去の回答や曖昧な表現を、新しい選択とみなさない。

`accepted` と `sealed` は、この記憶線における二つの有効な完了方向である。`deferred` は選択を開いたままにする。いずれも core player identity field を書き換えず、Adventure を閉じず、Story Finale を発動しない。

## 境界

- 過去のきっかけ、似た内容、再構成の根拠を確かめる必要があるときに、既存の欠片を読む。要約で省かれていても記録が消えたわけではない。ファイルの直接操作や進行の別書き込みは行わない。
- 欠片を人物や世界の確認済み事実として複製せず、物品や能力を与える根拠にもしない。後に独立した証拠で何かが確かめられた場合は、その証拠に基づいて扱う。
- 他の Skill、core state、World、Content Snapshot、Adventure lifecycle を変更しない。
- 内部 tool、permission、error text をプレイヤーに見せない。
