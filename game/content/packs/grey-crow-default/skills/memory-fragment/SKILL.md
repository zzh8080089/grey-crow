# 记忆碎片

这是一条由玩家选择开启的叙事成长线。主持人可以在玩家主动探索角色模糊的个人过去或遇到强关联场景时，把模糊、未经证实的
感官片段追加到本局模块；玩家可以在右侧扩展槽查看进度、阶段、四个维度和完整列表。

这份说明只适用于玩家为本局选择启用的记忆碎片玩法；读到说明本身不代表已启用。不要把它和
长期记忆检索、已确认的世界事实、核心身份或故事终局混为一谈。

## 何时可以产生碎片

- 玩家明确尝试探索角色模糊的个人过去或身世，可以产生一条“主动回忆”碎片。
- 回想本局已经发生的观察或对话属于前情检索，不自动生成新的个人过去碎片。
- 当前人物、物品、气味、声音、动作或地点与角色过去形成强关联，可以产生一条“被动浮现”碎片。
- 每个游戏日最多一条主动回忆和一条被动浮现；没有自然触发时不要为了增加进度而生成。
- 当日限额只限制新发现；读取或重访已有碎片不消耗发现额度，也不自动新增碎片。来源里没有的细节仍然未知。
- 开局创建和确认当轮不产生碎片；只有确认开局后的自由冒险才可触发。
- 同一触发物不重复；新片段不能与已有内容高度相似。
- 每条只属于身体、情感、技能、身份四个维度之一。

普通休息、重复查看背包、随口提到“以前”或单纯为了凑数，都不是充分触发条件。Skill trigger 只帮助
发现本说明，不是自动生成器。

## 碎片写法

- 使用 2-4 句具体但不完整的感官内容，可以包含动作惯性、情绪反应、声音、气味、触感或短暂画面。
- 保持 `uncertain`：碎片只是一种可能的过去，不是 NPC、World 或 Semantic Memory 已确认事实。
- 不直接说出完整身世，不替玩家确认真实姓名、阵营、罪责、亲属关系或唯一身份。
- 不把模型推理、提示词、文件路径、工具过程或来源分析写进碎片。

## 叙事与记录一致

本说明提供玩法标准；可用操作、字段和恢复方式以当前引擎协议为准，不另设写入工具或重试流程。

- 新碎片的完整内容必须以相同措辞出现在本轮玩家可见的叙事中，不能只描写触发物而把碎片藏在记录里。
- 碎片记录、玩家的拼合选择和对应正文随整轮故事一起校验、提交，不先单独写入。编号、日期、来源和进度由引擎管理。
- 整轮未成功提交时，不能把新碎片或选择当成已经发生，也不能推进进度。取消、失败和重试交由引擎处理。
- 修正时若撤去新碎片或选择，也须移除或改写正文中对应的新碎片或已作出选择的描述；其他有效叙事可以保留，但仍须整轮成功提交。
- 本局最多 30 条，不靠改变日期、重复触发物或其他写入方式绕过限额。

## 拼合记忆

第 30 条只解锁自然的“拼合记忆”时刻；该轮不作拼合选择。确认解锁后的后续回合中，主持人通过
正常叙事让玩家自由选择。满额不会自动结束冒险，也不会自动证明过去为真；玩家没有明确表达时不得代选：

- 接受过去：使用 `choice=accepted`。玩家获得“恢复记忆者”称号，表示主动接受了
  这份自我叙事，不代表系统证明它是绝对历史。
- 不接受过去：使用 `choice=sealed`。保留全部碎片作为经历，但明确允许玩家放下过去、选择并塑造
  一个新的自己；这不是失败路线，也不应受到惩罚。
- 暂缓决定：使用 `choice=deferred`。以后玩家再次明确面对这段过去时，仍可选择接受或不接受。

只在玩家本轮明确作出选择后，按当前引擎协议把这一选择与对应叙事一起提交。不能把旧回答或模糊表达当作新的选择。

`accepted` 与 `sealed` 是这条记忆线的两个有效完成方向；`deferred` 保持选择开放。三者都不能改写
核心玩家身份字段、关闭 Adventure 或触发故事终局。

## 边界

- 需要核对旧触发物、相似内容或拼合依据时，按需读取已有碎片；摘要省略不代表原记录消失。不直接操作文件或另写模块进度。
- 不把碎片复制为已确认的人物或世界事实，也不凭它授予物品或能力；若剧情后来独立证实某件事，按那份独立证据处理。
- 不修改其他 Skill、核心状态、World、Content Snapshot 或 Adventure lifecycle。
- 不向玩家暴露任何内部工具、权限或错误正文。
