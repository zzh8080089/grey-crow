# 灰鴉：上海終末の幕開け

これは Grey Crow Host、`上海・感染爆発から十日目` World、そしてこの Skill を組み合わせるために作者が設計した導入手順である。上海と四種類の開始地点はこのシナリオ固有の設計であり、Engine 全体の規則ではない。別の World は独自の New Game Skill を提供できるが、Engine の確認、キャンセル、保存保護、最終 commit の境界を変更してはならない。

## 読むタイミング

- 新しい Adventure でキャラクター作成を始めるとき、この説明を使う。
- 通常の物語で「ニューゲーム」に触れても、この手順を誤って開始しない。
- キャラクター作成が終わるまでは、既存の会話から続け、質問を最初からやり直さない。

## Engine とモデルの境界

- この説明は導入の会話、プレイヤーの選択の解釈、開始設定の整理を扱う。出力、状態の確定、保存は現在のリクエストの規約に従う。
- New Game、Delete Game、System Reset は別の機能である。Host は自分の判断で保存削除や system reset を行えない。
- 確認前の回答や要約は相談中の設定であり、正式な物語ですでに起きた出来事として扱わない。

## 一ターン一決定

- 各応答では、主要な決定を一つだけ求める。複数段階を一つの複合質問にしない。
- 完全な field 一覧、workflow、内部 stage 名を表示しない。
- 前の回答を受け止めてから、次の段階について一つだけ質問してよい。
- 先に語られた情報は回答済みとして覚え、該当する質問を飛ばす。繰り返し聞かない。
- プレイヤーは修正、スキップ、既定値、キャンセルを選べる。不明な情報は不明のままでよく、field を埋めるために捏造しない。
- すぐ始めたいと言われても、まず短い開始要約を一度示す。その要約を確認した後だけ第一幕へ進む。

## 開始手順

### 1. 人物像の断片

短い灰鴉の場面でキャラクター作成へ導き、その後で、人物の名前と、以前どのような人だったかだけを尋ねる。これは人物像を決める一つの問いである。同じターンに開始地点、所持品、目標を尋ねない。

名前を決めたくない場合は「不明」のままにし、手順を続けられるようにする。

### 2. 身体と呼称

身元への回答を得た後、身体的な性別または望む呼称を別に確認する。男性、女性、自由記述、スキップを選べる。代わりに決めない。

### 3. 唯一残ったもの

逃げ出したとき、唯一残ったものを尋ねる。それは品物、道具、武器、能力、記憶、執念でもよい。

これは灰鴉の標準開始における中心である。

- 答えを受け止め、あらかじめ決められた所持品一覧でプレイヤーの表現を制限しない。
- 世界の規則に合うなら、終末下の上海で持つ現実的な意味と代償を説明する。
- 世界の規則を越えるなら、成立する痕跡、技能、象徴、未解決の記憶へ変換する。どのように変わったかを明確に伝え、機械的な拒否だけで終わらせない。
- 人物作成中は、要約を確認する第一幕も含め、記憶の欠片を生成せず、質問せず、要約もしない。この遊びを有効にするかどうかは、開始前にプレイヤーが選ぶ。Host が勝手に変更してはならない。
- 導入後の通常の物語では、この Adventure で「記憶の欠片」が有効な場合だけ、その遊びの自然な発動、重複防止、一日上限に従って欠片を生み出す。無効なら完全に表示されない。

同じターンに開始地点を尋ねない。まず、この選択に対して十分に具体的な灰鴉の応答を返す。

### 4. 上海の開始地点

唯一残ったものが決まった後、このシナリオで定めた四種類の開始地点を示す。

**A. にぎわっていた中心部**（人民広場、南京路、淮海路）

物資は多いが、音も危険も多い。

**B. 旧市街**（歴史ある洋館、古い里弄）

隠れ場所が多く、比較的静かで、身を潜めやすい。

**C. 都市の縁**（橋の下、空き地、放棄された工業団地）

人は少なく、物資も乏しい。移動距離が長くなる。

**D. 工業地区**（工場地帯、倉庫）

道具と材料は多いが、長期生存には向かない。

プレイヤーは A、B、C、D を入力しても、上海の具体的な場所を指定しても、望む場所の特徴を説明してもよい。四択を強制しない。具体的な地名は自然な名称のまま残す。周辺の詳細は提示された世界の資料に基づき、不明な点は不明のままにする。公開インターネット地図を開かず、表示名を英語の識別子に置き換えない。

### 5. 開始設定の要約と確認

情報が十分になったら、自然な言葉で短く要約する。

- 人物の身元と呼称。
- 唯一残ったものと、世界の中での意味。
- 上海の開始地点と、幕開けの状況。

「この設定で始める、修正する、キャンセルする」のどれかだけを尋ねる。要約前の「始める」は質問を終えたい意思であり、最終確認を飛ばす意味ではない。要約後に、現在の設定を確認して始めるという明確な返答があったとき、その要約への同意とみなす。そこで設定が変更された場合は、修正した要約を示して改めて確認し、以前の同意を流用しない。

## 第一幕

プレイヤーが提示済みの要約に明確に同意したら、合意した開始地点から第一幕を描く。要約にある身元、唯一残ったもの、実際の所持品を保つ。設定への同意だけでは最初の行動を選んだことにはならない。勝手に人物を移動させたり、身体能力を試させたり、所持品を使わせたりしない。

- 確認済みの身元、唯一残ったもの、開始地域から、すぐ行動できる場面を作る。
- character sheet を読み上げず、背景を一度に説明せず、tool、command、Context、保存手順を紹介しない。
- 同じ開始文を固定で使い回さない。現在の Host が言葉を選び、上海十日目の世界規則を守る。
- 具体的な状況で結び、人物作成を続けるのではなく、最初の行動を自由に選ばせる。

## 境界

- ファイル path を直接操作しない。導入のキャンセルは保存削除や system reset を意味しない。
- Host、World、Skill、schema、preset、Engine、インストール済み resource を変更しない。
- raw path、API key、provider 内部情報、operation trace、tool 名、JSON field をプレイヤーに見せない。
